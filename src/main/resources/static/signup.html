And about the JobRunr docs

The same server searches the JobRunr documentation, so your agent answers from the current docs and links the page. This part works without an account.

Claude Code + JobRunr MCPdocs search
YouMy invoice job has retries switched off. How do I turn automatic retries back on?
Agent

Retries are usually switched off in one of three places. Check them in this order:

1. On the job method (most likely). Look for @Job(retries = 0). Either delete retries so the job uses the global default of 10 attempts, or set a number:

@Job(name = "Generate invoice", retries = 5)
public void generateInvoice(...) { ... }

2. Global setting. If jobrunr.jobs.default-number-of-retries=0 is set […], remove it or raise it. […]

Docs: jobrunr.io/en/documentation/background-methods/dealing-with-exceptions

How it works

Your application opens an outbound connection to mcp.jobrunr.io. Your agent talks to the same place with its own token.

Your AI agentClaude Code, Cursor, VS Code
asks→
JobRunr MCPmcp.jobrunr.io
calls out←
Your applicationJobRunr + one dependency
no inbound port
  1. Sign up and confirm your email. You get a connector token and an agent token.
  2. Install the plugin with your favorite build tool. It needs Java 17 and JobRunr 8.5.0 or later. 
    <dependency>
    <groupId>org.jobrunr</groupId>
    <artifactId>jobrunr-mcp</artifactId>
    <version>1.0.0-beta.1</version>
</dependency>
    implementation("org.jobrunr:jobrunr-mcp:1.0.0-beta.1")
  3. Add the connector token to your application config. One line: 
    jobrunr.dashboard.mcp.token=jrc_read_…
  4. Add the agent token to your MCP client. One URL, one header. Your account page gives you the exact command for Claude Code and Cursor.

You stay in charge

Read-only unless you choose otherwise

The token decides. With a read-only token your agent can look at every job and change none of them.

A dry run before every bulk action

Your agent gets a preview with the exact jobs and shows it to you. Nothing is requeued until you say yes.

Start on a test environment

Job names and parameter values are sent as they are stored. Try it first where the job data is safe to share with your agent.
